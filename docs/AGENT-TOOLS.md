# Agent tools

How agents start sessions and hand work back through Shepherdr: the `shepherdr` command and skill Shepherdr installs on each machine, the letters they leave, and how Shepherdr collects them. The [guide](GUIDE.md#agents-that-coordinate) explains what you see.

The design rests on one constraint: **machines never connect to the Mac.** Remote servers are often locked down, and they can't reach a laptop anyway. The command only talks to its machine's Herdr, and through it to the machines Herdr saved. Anything for Shepherdr becomes a letter on disk, announced by a Herdr pane token. Shepherdr fetches letters over the SSH connection it shares with its other commands to that machine, with the same options as for terminals and dropped files: `BatchMode=yes`, `StrictHostKeyChecking=yes`, no agent or port forwarding.

## What ships and where it goes

The kit lives in `Sources/ShepherdrCore/Resources/AgentTools` and is bundled in the app:

```text
AgentTools/
  VERSION                     tools version, an integer
  bin/shepherdr               the command: POSIX sh, needs only herdr
  skills/shepherdr/SKILL.md   the skill, the same for Claude Code and Codex
```

On each machine, the installer writes:

```text
~/.shepherdr/
  VERSION, bin/, skills/      the kit
  machines                    this machine's list, written by Shepherdr
  outbox/<id>/                letters waiting for Shepherdr
  outbox/.collected/<id>/     collected letters, cleared after a week
  inbox/<machine>/<id>/       on the Mac: letters Shepherdr collected, kept for a month or while mail needs them
~/.claude/skills/shepherdr/                if ~/.claude exists
${CODEX_HOME:-~/.codex}/skills/shepherdr/  if that folder exists
```

The installer is a script generated by `AgentTools.installScript`: every file of the kit as a quoted heredoc, sent on standard input to `sh -s` over SSH (or `/bin/sh -s` on the Mac), with `umask 077`. Files go into a staging folder inside `~/.shepherdr`, then into place with `mv`, `VERSION` last. Skills are copied, not linked, and moved into each agent's folder in one step, so an agent never sees a half-written skill. The machine list goes in on the same trip.

**Bump `VERSION` whenever you change the kit.** Machines only update when the bundled version is greater than theirs. `AgentToolsTests` keeps each version's fingerprint and fails when the files change under the same version.

## Checking a machine

`AgentTools.checkScript` answers in one trip:

```text
shepherdr-tools 1                  installed version, or -
shepherdr-list 3f2a9c1b7e04        revision of ~/.shepherdr/machines, or -
shepherdr-system Linux x86_64
shepherdr-agent claude yes yes     agent folder present, skill installed
shepherdr-agent codex no no
shepherdr-outbox 2                 letters not collected yet
```

Shepherdr checks each machine the first time it is online after launch, again when you open one of its sessions if the last check is ten minutes old, and on every manual refresh. Waiting letters are collected on the same occasion. An agent folder without the skill gets it right away; an outdated kit is offered for updating, updated, or left alone, as **Settings → Agents → Updates** says.

## Machine lists

`MachineList.entries(for:machines:macName:shares:)` gives each machine its own view, tab-separated after a header:

```text
# shepherdr machines 1 rev 3f2a9c1b7e04 2026-10-15T10:15:02Z
buildbox	here	-
Studio	shepherdr	-
```

Routes are `here` (this machine), `direct` (its Herdr reaches the machine through the profile in the third column; only the Mac's list has these) and `shepherdr` (only Shepherdr reaches it, after the user approves). Names are one line, unique ignoring case; the Mac goes by its computer name or the one set in Settings. The revision is a hash of the lines, so Shepherdr compares it with the one the last check found and rewrites a list only when it changed. Disabled machines are left out, and a machine that doesn't share the list only gets its own line.

## Letters

The command writes each letter in `outbox/.tmp-<id>/`, then renames it to `outbox/<id>/`: Shepherdr never sees half a letter. IDs are a UTC time and a random suffix, `20261015T101502Z-7f3a9c`. Then it rings the doorbell:

```sh
herdr pane report-metadata "$HERDR_PANE_ID" --source shepherdr --token shepherdr-mail=<id>
```

Herdr reports the token in the snapshot's `panes[].tokens` (and `agents[].tokens`), so Shepherdr sees it within one refresh. Tokens follow the terminal across agent changes and pane moves, and are lost when the Herdr server restarts, which the manual sweep covers.

A letter is `letter.json`, an optional `message.md`, and attachments in `files/`. The JSON only holds fixed-format values the command checked: IDs, names, kinds, links, and paths that it escapes. Free text, such as a message or a prompt, goes in `message.md`, never in the JSON. Every letter has:

```json
{"protocol": 1, "id": "20261015T101502Z-7f3a9c", "kind": "handoff",
 "from": {"pane": "w4:p1", "terminal": "term_65d6bd22d314d2"}}
```

`from` is `{}` outside Herdr. The kinds add:

| Kind | Written by | Fields | Shepherdr |
| --- | --- | --- | --- |
| `spawned` | `spawn` | `child: {machine, pane, terminal, workspace}`, `name`, `agent`, `placement`, `wait`, `prompt` | Places the child after its parent, in its group; makes the parent wait unless `wait` is false; a `pending` prompt (in `message.md`) waits for the agent to be free |
| `spawn-request` | `spawn` to a `shepherdr` route | `machine`, `cwd`, `agent`, `name`, `wait`, `prompt` | Starts the session once you approve, linked like `spawned` |
| `handoff` | `handoff` | `to`, `body`, `files` | Delivers it as a prompt to the sessions waiting for the sender, or to `to` |
| `wait`, `resume` | `wait-for`, `resume` | `sessions` | Adds or removes holds |
| `pin` | `pin` | `url`, `title` | Adds the link to the sender's resources |
| `open` | `open` | `url` | Opens it in the sender's browser |
| `notify` | `notify` | `body` | Posts a notification |

`child.machine` is `here` or `profile:<Herdr profile ID>`; the latter only counts in the Mac's own letters. Names in `to` and `sessions` match a session's Herdr agent name, then its workspace name, ignoring case, preferring the sender's machine; `name@machine` picks the machine.

`Letter(id:contents:)` checks everything again: the protocol version, that the ID matches the folder, IDs' and names' characters, lengths, http(s) links, attachment names (`files/` and `[A-Za-z0-9._-]`), that listed attachments came along, and the 256 KB message limit, which the command also enforces on messages and prompts. A letter that fails is set aside with a notice; nothing in a letter ever runs.

## Collecting

On a doorbell, Shepherdr runs `Mailbox.collectScript` on the machine. It prints the waiting letters, oldest first, as one stream:

```text
shepherdr-mail 1
L 20261015T101502Z-7f3a9c
F 171 letter.json
<171 bytes>
F 7 files/REPORT.md
<7 bytes>
D 0
```

Only regular files (no symbolic links) with the names the command writes cross. A trip stops at 50 letters or 7 MB, and `D 1` says more are waiting; the command keeps a letter's attachments under 5 MB. A letter over 7 MB, which the command never writes, comes as `L <id>` and `T <bytes>` without its files: Shepherdr files it unread with a notice, so it can't hold up the letters after it. Shepherdr keeps each letter in `~/.shepherdr/inbox/<machine>/<id>/` (folders `0700`, files `0600`), records its ID, and only then runs `Mailbox.acknowledgeScript`, which moves the letters to `outbox/.collected`. A trip that fails halfway collects the same letters again, and the recorded IDs keep them from being applied twice. Kept letters are cleared after a month, unless mail still waiting in Shepherdr refers to them.

## Delivering

`MailPlanner.plan` turns a letter into actions; `Courier` in the app carries them out. Handoffs and pending prompts are delivered with `herdr [--machine] agent prompt <pane> <text>` once the recipient's agent is idle or done, one at a time, at least 20 seconds apart per session. Herdr refuses while the agent shows a question or isn't ready, and Shepherdr tries again on a later refresh. For a recipient on another machine, attachments are first copied to its `~/.cache/shepherdr/drops`, as dropped files are.

Letters from the Mac apply on their own. From another machine, anything whose text would reach a session on a different machine, requests for sessions, and pages to open wait for the user, unless **Trust its letters** is on for that machine. A handoff between sessions on the same remote machine crosses nothing and is delivered directly.

**HANDOFF AND CLOSE** adds no letter kind. Once the session's agent is idle or done, `Courier` types `HandoffClose.prompt` into it with the same `agent prompt`, asking it to run `shepherdr handoff` without `--to`. `HandoffClose.outcome(of:)` then reads the actions planned for each letter collected. If a handoff from that session was filed for a session that waited for it, queued or waiting for approval, the message and files are on the Mac: Shepherdr closes the session with `pane close`, as **Close Session** does. A handoff filed for anyone else keeps the session open. So does a failed request, or no handoff within 15 minutes of asking while the agent isn't working. The pending close lives in memory only.

## Testing

```sh
sh Tests/AgentTools/test.sh             # the command against a fake herdr
TEST_SHELL=dash sh Tests/AgentTools/test.sh   # with another shell: dash, bash, busybox sh
sh Tests/AgentTools/herdr-live.sh       # against a real Herdr, in a server of its own
swift test --filter "AgentTools|Letter|Mail"
```

`test.sh` needs only POSIX tools. CI runs it on macOS, with dash and BusyBox on Linux, and ShellCheck. Spell out character sets in patterns instead of ranges such as `[a-z]`: bash matches ranges by the locale's collation, so under `en_US.UTF-8` `[a-z]` takes `B`. The scripts Shepherdr runs over SSH also set `LC_ALL=C`; the command leaves the locale alone. `herdr-live.sh` starts a Herdr server in a scratch home under `/tmp` (socket paths must be short), spawns shells from a pane and checks letters and doorbells; CI installs Herdr with Homebrew to run it. The Swift tests run the real command and scripts in a scratch home: what the command writes, the Swift side reads.

## Compass

Compass's agent is a session like any other, with a kit of its own in `Sources/ShepherdrCore/Resources/Compass`, bundled in the app and put in `~/.shepherdr/compass` on this Mac only. The [guide](GUIDE.md#compass) explains what you see.

```text
Compass/
  VERSION          kit version, an integer
  AGENTS.md        the contract: runs, files, sessions, the template, actions, marks, rules
  CLAUDE.md        @AGENTS.md, for Claude Code
  template.html    the page template: Shepherdr's look and the day strip's script
  prompt.md        the starter prompt
  settings.json    Claude Code's permissions, installed as .claude/settings.json
  gitignore        installed as .gitignore
```

`CompassFolder.prepare` writes the kit each launch by owner. `AGENTS.md` and `CLAUDE.md` are always rewritten. `template.html`, `.claude/settings.json` and `.gitignore` are rewritten only while their fingerprint matches the one Shepherdr recorded in `state.json` when it last wrote them. `prompt.md` and `compass.json` are written once. `settings.json` names the tools both by `~` and by the full path, since Claude Code matches commands as they're typed. **Bump `Compass/VERSION` whenever you change the kit:** `CompassTests` keeps each version's fingerprint.

### Runs

Shepherdr types one prompt per run, once the agent is idle or done, nobody typed to it for two minutes, and no handoff for it is queued:

```text
Compass run · update · Thu 2026-10-15 14:00
Since 13:02, when the last run finished.
Follow prompt.md. Today's page is days/2026-10-15.html; context/run.json has the details of this run.
```

Right before it, Shepherdr writes `context/run.json` (`kind` first, update or last; `trigger`; `slot`; `since`; `page`; `previous`; `marks`; `time_zone`; `language`; `strip`; `schedule`) and `context/sessions.json`. A run is over when the agent goes idle or done after working, or a minute after the prompt if Herdr never saw it work. It updated the page when the page's modification date is later than the prompt. Then Shepherdr copies the page to `days/<day>/HH-MM.html`, deletes copies older than 14 days, and commits the folder.

`CompassSchedule.dueSlot` decides when: the latest of today's run times that has passed and that no run started since. Runs missed on earlier days are never made up. The day's first run, when no run started today, closes every pane in Compass's workspace and folder and starts a fresh agent; the sessions the old agent waited for wait for the new one.

### The page's actions

The page is a local file loaded with a `WKWebViewConfiguration` of its own. `CompassBridge` adds a user script in a `WKContentWorld` named `shepherdr-compass`, and the message handler only in that world, so the page's own scripts can't reach it. The script listens for clicks, in capture, with `event.isTrusted`, on elements with `data-shepherdr`, and posts their `data-*` attributes, with `data-item` from the element or an ancestor. The handler only takes messages from the main frame of a file inside `~/.shepherdr/compass`, and `CompassAction` checks every field before anything happens:

| `data-shepherdr` | Fields | Shepherdr |
| --- | --- | --- |
| `spawn` | `machine`, `cwd`, `kind` (an agent kind or `shell`), `name` (`[a-z][a-z0-9_-]{0,31}`), `prompt` (256 KB at most) | Opens New Session with them filled in. The first prompt waits in the mail like a spawned session's, in `~/.shepherdr/inbox/compass/<id>/message.md`, deleted once delivered or discarded. With **Hand its result back to Compass**, Compass's agent waits for the session, so its handoff comes back. The item records it under `started` in the day's marks. |
| `ask` | `prompt` | Puts the text in Compass's prompt editor. |
| `session` | `session`, `name` or `name@machine` | Switches to Agents and opens it. |
| `prompt` | `session`, `prompt` | Opens it with the text in its prompt editor. |
| `done` | `item` | Toggles the item in `days/<day>.marks.json`'s `done`. |

A field that is there and doesn't hold up refuses the whole action. On every refresh, Shepherdr calls the script's `apply` in the same world with each session's state, by agent and workspace name and `@machine`, and the day's marks: elements with `data-session` get a state badge, done items a class, and started sessions a note beside their button.

`shepherdr spawn` from Compass's agent works as from any agent: the CLI starts the session, Shepherdr places it at the end of the queue rather than after Compass, and Compass waits for it. Claude Code's permissions in the folder ask before `spawn`, `handoff`, `agent prompt` and `agent start`, since the agent reads what others wrote.
